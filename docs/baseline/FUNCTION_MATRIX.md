# `news` 到 `news_writer` 功能矩阵

## 1. 文档用途

本文档是阶段 1 的行为基线。它只读分析原项目 `<legacy-news-root>`，用于回答四个问题：原项目实际做什么、纯 TypeScript 产品应做什么、哪些差异需要保留或主动修正、后续用什么证据验收。

本矩阵不是 Python/PowerShell 迁移清单。目标行为以 `news_writer/GOAL.md` 为最高产品依据；原项目只提供功能规格、业务规则、Prompt、写作规范、输入输出样例和行为参考。原项目中的文件名推断、静默降级、一次性资料治理等实现细节，不因“现有行为”而自动成为兼容要求。

状态说明：

- **保持**：保留业务含义，允许用新的 Schema、IPC、UI 和 TypeScript 实现。
- **重设计**：保留用户目标，但明确不兼容原来的文件式或隐式实现。
- **新增**：`GOAL.md` 要求、原项目没有的正式产品能力。
- **排除**：首版不得实现或暴露。

## 2. 主要证据

| 证据 | 用途 |
| --- | --- |
| `news/README.md` | 日常生成、审稿、续改、两类稿件、输出和参数的用户可见说明 |
| `news/run_news.ps1`、`run_other_news.ps1` | 生成入口、纪要选择、干跑、缺项补充和二次审稿编排 |
| `news/revise_news.ps1`、`revise_other_news.ps1` | 续改入口、反馈采集和场景选择 |

| `news/scripts/generate_news.py` | 生成 Prompt、检索报告、干跑、初稿和正式输出 |
| `news/scripts/review_news.py` | 二次审稿 Prompt、补充信息和终稿清理 |
| `news/scripts/revise_news.py` | 文件式历史稿选择、上下文收集、轮次和历史文件重命名 |
| `news/scripts/ingest_sources.py`、`build_index.py` | 语料清理、脱敏、培训规则抽取和 BM25 索引格式 |
| `news/data/training_rules.txt` | 标题、首段、正文、称谓、落款、字体、字号、缩进和送审规范 |

建议的黄金用例代号：`G-OFFICIAL`（资料完整的学院稿）、`G-OTHER`（其他场景稿）、`G-MISSING`（缺时间/地点/主体）、`G-NOHIT`（无检索命中）、`G-REVIEW`（补充后审稿）、`G-REVISE`（批注续改）、`G-BRANCH`（回溯后分支）、`G-ERROR`（错误/取消/超时/空响应）、`G-DOCX`（渲染基准）。这些代号描述验收覆盖，不代表对应 fixture 已由本文创建。

## 4. 必须保留的业务不变量

1. 活动纪要及用户明确补充是新稿事实来源；历史稿不是事实来源。
2. 学院稿不得写错主办关系，其他稿不得无依据套用学院主体、称谓或落款。
3. 系统生成的上下文在进入检索和 AI 前按规则脱敏；API Key 永不进入项目或任务内容。
4. 缺失事实可以提示、补充或避开，不能编造；可导出终稿不含待补充占位或内部问题清单。
5. 失败、取消、超时和空响应不能创建成功版本，不能覆盖或移动已有版本。
6. `latestVersionId` 是显式状态；切换最新版不删除分支。
7. 批注永久属于对应版本；只在该版本为最新版时可编辑；生成时快照该版本届时的批注，新版本不继承。
8. 历史检索记录保存实际进入 Prompt 的文本和知识库版本，不能靠未来重新检索来伪造复现。
9. DOCX 只在明确导出时生成，只含指定版本正文，并经实际渲染验收。
10. 原 `news` 始终只读；产品运行时不调用其 Python、PowerShell、源文件或输出目录。

## 5. 进入 Schema 阶段前的接口结论

- `Version` 只代表成功且非空的稿件；失败信息属于 `Task`，版本仅引用其成功任务及成功状态快照。
- `Task` 必须引用实际发送 Prompt、配置解析结果、父版本（如有）、批注快照（如有）和结果状态。
- `Comment` 必须以 `versionId` 为所有权边界，锚点与引用文本用于定位，不能以轮次或文件名归属。
- `RetrievalReport` 必须保存知识库版本、命中 ID/分数及实际引用文本，不保存原知识库绝对路径。
- `ExportRecord` 引用版本和样板版本；DOCX 不是版本的内容源，导出失败也不影响版本。
- `Project` 显式保存 `latestVersionId` 和归档状态；排序显示可使用 `createdAt`，但不得由时间推断最新版。
- AI 错误、取消和超时必须通过共享错误 Schema 传递；不能复刻原项目的 broad catch、静默降级或空结果落盘。

以上结论足以约束阶段 2 的 Schema 和纯领域层；具体依赖、字段名和迁移编号仍应按 `AGENTS.md` 的独立 agent 审查门禁确定。
