# News Writer 用户操作指南

适用版本：News Writer 0.1.x，Windows 10/11 x64。

News Writer 是一个新闻稿写作工作台。它保存活动纪要、Prompt、新闻稿版本、批注和任务记录，并在用户明确操作后导出干净的 DOCX。首版正式支持 DeepSeek。

## 一、首次启动

1. 从便携目录中运行 `News Writer.exe`。请保留整个目录结构，不要只复制或移动 exe 文件。
2. 在欢迎页点击“DeepSeek：未配置”或“DeepSeek 认证”。
3. 输入自己的 DeepSeek API Key，点击“保存”。覆盖或清除已有 Key 时需要再次确认。
4. API Key 只保存在当前 Windows 用户的本机安全存储中，不写入项目目录、Prompt、导出文件或日志。

使用者需要自行准备有效的 DeepSeek API Key 和网络连接。应用不要求额外安装 Node.js、Python、conda 或浏览器。

## 二、新建或打开项目

### 新建项目

1. 在欢迎页点击“新建项目”，或在“文件”菜单选择“新建项目”。
2. 输入项目名称，选择“学院新闻稿”或“其他新闻稿”。
3. 点击“选择目录并创建”，选择一个可写目录。
4. 项目打开后，左侧默认显示“活动纪要”。

### 打开项目

在欢迎页点击“打开项目”，选择包含 `project.json` 的完整项目目录。项目可以位于任意可写路径；不要只打开其中的某个 Markdown 文件。

项目正在其他窗口或进程中使用时，应用会提示项目锁。确认没有其他实例正在编辑后，再按提示恢复过期锁。

## 三、准备活动纪要

可以直接在左侧“活动纪要”编辑器中粘贴或输入内容，也可以通过“文件”菜单的“导入活动纪要”导入文本文件。导入格式为 `.md` 或 `.txt`。

纪要应尽量写清楚日期、时间、地点、举办或组织单位、参与人员、活动内容和新闻稿要求。应用的事实检查只提供核对线索，不会替用户证明事实。

编辑器会在停止输入约 1 秒后自动保存；也可以点击编辑器右上角的保存图标或使用 `Ctrl+S` 立即保存。自动保存尚未触发时，底部状态会显示“纪要有未保存修改”，此时不要立即关闭项目或开始下一步，否则最后几秒的输入可能丢失。

## 四、检索参考稿

底部工作栏的“参考稿检索”开关默认开启。点击“准备初稿 Prompt”时，应用会先保存未保存的活动纪要，再从随应用携带的只读知识库自动检索，并把命中稿件的标题和节选加入初稿 Prompt。用户不再需要单独点击左侧检索按钮。

关闭开关后，初稿 Prompt 会明确记录本轮未使用参考稿；切换开关会让已有 Prompt 过期，需要重新准备。若内置资源不可用，界面会显示“不可用”，不会伪装成零命中；可以关闭开关后继续准备初稿。

参考稿资源是应用内置的只读资料。首版没有知识库增删、扫描或重建入口。若资源暂时不可用，可以不使用参考稿继续准备初稿。

## 五、生成初稿

1. 点击底部“准备初稿 Prompt”。
2. 查看左侧“Prompt”标签中的内容和“事实检查”区域。
3. 若日期、时间、地点或举办单位显示“缺失”，回到“活动纪要”补充并保存，然后重新准备 Prompt。
4. 如需修改 Prompt，先点击“编辑 Prompt”，阅读风险提示并选择“我已了解，继续编辑”。修改可能破坏事实约束和写作规范，责任由使用者承担。
5. 确认内容后点击“生成新版本”。

任务区域只显示当前状态，例如“正在准备”“AI 正在处理”“已完成”“失败”“已取消”或“已超时”，不显示虚假的百分比进度。任务进行中可以点击“取消任务”；取消只停止本地等待，不保证服务端已经停止处理，也不保证不会产生服务端费用。任务进行期间，纪要保存、批注增删改、项目配置修改、导出和版本切换等操作会被暂时禁用，避免与正在进行的生成相互冲突。

成功生成的版本不可变。失败、取消或超时不会覆盖已有版本，也不会产生一个成功的空版本。

## 六、AI 二次审稿和续改

### AI 二次审稿

1. 在已有版本后点击“AI 二次审稿”。
2. 检查生成的审稿 Prompt，必要时编辑。
3. 点击“生成新版本”。审稿成功后会产生一个新的子版本，原版本仍保留。

二次审稿会在一次任务内自动完成，不再单独弹出“补充信息”填写窗口；需要补充或更正的事实请先写回活动纪要，再重新准备 Prompt。

### 批注和按照批注更新

1. 确认右侧显示的是“当前最新版”。
2. 在正文中选择需要修改的文字，批注区默认开启；也可以点击气泡图标打开。
3. 点击“为所选文本添加批注”，输入修订意见并点击“保存批注”。
4. 需要修改意见时使用“编辑批注”；引用位置变化时，先在最新版重新选择文字，再使用“重新锚定”。
5. 点击“按照批注更新 Prompt”，检查修订 Prompt 后点击“发送当前 Prompt，生成新版本”。

批注始终属于它所绑定的版本。续改时，该版本的批注会作为本轮 Prompt 的快照；新版本不会自动继承这些批注，若仍需修改，必须在新版本上重新批注。批注不会导出到 Word。

## 七、历史版本、分支和差异比较

1. 展开资源栏，在“版本关系”中查看版本树。
2. 点击任意版本可在左侧“历史稿”中查看。
3. 选择历史版本后点击“与最新版比较”，查看差异；点击“退出比较”返回正文。
4. 如需回到某个历史版本，点击该版本下的“设为最新版”，确认操作。

“设为最新版”只移动当前最新版指针，不删除之后产生的版本或分支。历史版本的批注会随版本保留；当该版本重新成为最新版后，可以继续编辑这些批注。从历史版本继续生成会形成新的分支。

## 八、导出 DOCX

1. 在版本关系中选择要导出的版本；未选择历史版本时，默认使用当前最新版。
2. 点击中右侧“当前最新版”栏中的“导出 DOCX”按钮。按钮按当前选中版本导出；选择历史版本后仍可导出该历史版本。
3. 选择目标位置并确认导出。
4. 在资源栏的“导出记录”查看成功或失败记录。

导出的 Word 文件只包含新闻稿本身，不包含批注、Prompt、检索信息、问题清单或内部任务数据。导出失败时，已有版本不会被修改；请根据提示更换可写目录、关闭占用文件的程序或检查磁盘空间。

## 九、归档、恢复和备份

在“项目”菜单选择“归档或恢复项目”。归档只改变项目状态，不删除版本，也不会把稿件加入知识库。归档项目为只读；需要继续编辑、批注或生成时，先恢复项目。

建议在应用关闭后复制整个项目目录作为备份。项目目录中包含：

- 活动纪要和非敏感项目配置；
- 全部版本及版本关系；
- 批注、实际发送的 Prompt、任务记录；
- 检索记录和导出记录。

项目目录不包含 API Key、应用运行环境或应用内置知识库。不要只复制 `project.json`，也不要把外部导出的 DOCX 当作项目备份的一部分。

## 十、常见问题

### 提示“请先配置 DeepSeek API Key”

打开“DeepSeek 认证”重新保存 Key。Key 只对当前 Windows 用户和本机有效，复制项目不会带走 Key。

### 提示 Prompt 已过期

纪要、配置、检索结果、最新版或批注发生变化后，旧 Prompt 可能过期。选择“重新生成 Prompt”最稳妥。对已经发送过的初稿 Prompt，应用会要求重新准备，避免同一初稿在已有最新版之后触发项目状态冲突。续改 Prompt 在确认后才允许继续使用旧文本。

### 提示 Prompt 未发生变化

应用会比较当前 Prompt 与最近一次实际发送的 Prompt。续改 Prompt 相同时，可以明确确认后继续；初稿 Prompt 相同时，如果已经存在成功版本，应重新准备后再生成，避免状态冲突；如果上一次初稿失败或取消且尚无成功版本，可以明确确认后重试。

### 项目显示为只读

检查项目是否已归档。通过“项目”菜单恢复后才能保存纪要、编辑 Prompt、批注或生成版本。

### 任务失败、超时或被取消

查看任务区域的安全错误信息和诊断编号，确认网络、Key、模型配置和超时设置后重试。原有成功版本不会被覆盖。

### 关闭或切换项目时出现未保存提示

返回“活动纪要”或“Prompt”保存草稿；若选择放弃并关闭，未保存的本地编辑内容会丢失。

## 十一、交付给其他人使用

### 你需要交付什么

在开发机的 `news_writer` 目录运行：

```powershell
corepack pnpm package:dir
```

打包成功后，交付完整的 `release/win-unpacked` 目录，或将该目录整体压缩后交给对方。对方解压后运行其中的 `News Writer.exe`。

不要只发送 exe，也不要发送源码目录、`node_modules`、测试产物、QA 的 PDF/PNG/DOCX、Python 或 LibreOffice。便携目录已经包含运行所需的 Electron/Chromium 和应用资源。

交付前建议在干净的 Windows 10/11 x64 机器上启动一次并完成基本冒烟检查。当前首版没有安装包、自动更新或正式代码签名；未签名程序可能触发 Windows SmartScreen 提示，应通过可信的内部渠道交付并核对文件来源。

### 当前图标和签名状态

- 当前没有单独的品牌 `.ico` 资源，便携包使用 Electron 默认应用图标；`electron-builder` 配置尚未设置 `win.icon`。
- 当前可执行文件：`release/win-unpacked/News Writer.exe`。
- 当前版本：`0.1.0`；产品名：`News Writer`；Electron：`43.3.0`。
- 当前 Authenticode 状态：`NotSigned`，没有签名证书或发布者身份，不能把它当作已签名版本分发。
- 当前便携包可执行文件 SHA-256（2026-08-12 重打包）：`4420524D0E09CB7370DE9081B76A3DEAA197196C161D578980DBCF9C6525B135`。
- 当前 PE 版本信息中的公司名仍为 Electron 默认值 `GitHub, Inc.`；正式分发前应先确定品牌图标、发布者名称和代码签名证书，再更新 builder 配置并重新生成整包。

### 对方第一次使用

1. 解压完整便携目录到本地可写位置，不要从压缩包内直接运行。
2. 运行 `News Writer.exe`。
3. 在“DeepSeek 认证”中配置对方自己的 API Key。
4. 新建项目，或打开你另外交给他的项目目录。

对方不需要安装 Node.js、Python、conda、浏览器或单独的 Electron。对方必须自行承担自己的 DeepSeek API Key、网络访问和 API 使用费用。

### 把已有项目交给对方

关闭 News Writer 后，将整个项目目录单独复制或压缩交付。项目复制到对方电脑后，活动纪要、版本、批注、Prompt、检索记录和导出记录都会保留；API Key 不会随项目复制，对方首次使用时必须重新配置。

应用目录和项目目录应分开保存。升级应用时替换完整的便携目录即可，项目目录无需放进 `release/win-unpacked`；替换前先关闭应用并备份项目目录。
